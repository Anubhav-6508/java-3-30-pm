QUESTION 1 — E-COMMERCE CART & PRODUCT PRICING
============================================================

A shopping application sells Regular Products, Electronics, and Grocery Items.
Each product has a product ID, name, base price, and available quantity.

Requirements:
1. Product ID must be unique within the product objects handled by the program.
2. Price and quantity cannot be negative.
3. Electronics may have a warranty charge added to the base price.
4. Grocery items may have a discount based on their expiry date category
   (for this assignment, use a simple field such as discount percentage).
5. Each product type must calculate its final price differently.
6. A cart must be able to accept different product types and calculate the
   total without checking each product type in the cart's total-calculation code.
7. The application must display product details and final price.

Tasks:
Design the classes and relationships. Implement a demonstration with at least
one object of each product type.

Interview follow-ups:
- What should be common in the parent type?
- Which method should be overridden?
- How can the cart calculate totals without a long if/else chain based on type?
- Should product price be public? Why?
- If a new product category is added, which existing code should ideally remain unchanged?

QUESTION 3 — RIDE-HAILING FARE CALCULATOR
============================================================

A ride-booking application supports Mini, Sedan, and SUV rides.

Requirements:
1. Each ride stores ride ID, distance, and passenger count.
2. Distance must be positive.
3. Mini fare = base fare + distance * mini rate.
4. Sedan fare = base fare + distance * sedan rate.
5. SUV fare = base fare + distance * SUV rate.
6. SUV must reject passenger counts above its capacity.
7. A booking object should calculate the fare using the ride object it receives,
   not by checking whether it is Mini, Sedan, or SUV.

Tasks:
Design the classes and implement a fare-calculation demonstration.

Interview follow-ups:
- Which method should be abstract?
- How does runtime polymorphism help the booking component?
- Why would a type-checking chain in the fare calculator be a maintenance problem?
- What happens if a new ride category is introduced?

============================================================
INTERVIEWER GUIDANCE / STUDENT EXPECTATIONS
============================================================

For each scenario, students should be expected to:
1. Identify classes from the requirements.
2. Identify common fields and common behavior.
3. Identify specialized fields and behavior.
4. Choose and justify inheritance, composition, or interface.
5. Apply encapsulation and validation.
6. Use constructors correctly.
7. Apply method overloading only where it makes sense.
8. Apply overriding for specialized behavior.
9. Demonstrate polymorphism through parent/interface references.
10. Explain how the design accommodates a new product type.

Do not accept answers consisting only of OOP definitions.
Ask students to explain why they chose a design, draw a class relationship,
write the key classes, demonstrate at least three different concrete objects,
and test both valid and invalid inputs.

Suggested difficulty: 7.5–8.5/10 for fresher interviews.
